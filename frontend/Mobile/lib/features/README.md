# Feature modules

Every feature owns `data/`, `domain/`, and `presentation/` layers. Add remote/local data sources, API models, repository implementations, domain entities/contracts/use cases, then pages/widgets/Riverpod providers in that order.

Feature directories prepared for implementation: onboarding, doctor, chamber, staff, patient, appointment, queue, consultation, vitals, diagnosis, investigation, reports, medicines, prescription, payment, notifications, ai, analytics, settings, and profile.
